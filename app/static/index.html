No dedicated "safety car" / "pace car mode" field exists anywhere in the protocol -- the pace car is just address 7, driven the same way as any other address (see Speed/Brake below), and PACE CAR/ESC (in Buttons below) simulates the CU's own physical button for it. If that button does put the CU into some distinct mode, it isn't a separate status field -- watch start/mode/display above for any change when you press it; that's the only way to find out empirically.

Manual CU commands

Every one of these fires exactly once, exactly when you click it -- nothing here runs automatically. This is how to empirically test what the CU protocol can and can't do: e.g. does a speed/brake write to a controller address (0-5) actually affect a car with a live physical controller plugged into that slot, or does the real controller just win? There is no readback for speed/brake/throttle anywhere in the protocol -- the CU's poll() response has a fixed shape (8 fuel bytes + start + mode + pit + display, confirmed from the wire format) with no room for one, so the only way to confirm a write did anything is to watch the physical car/track, not this page.
